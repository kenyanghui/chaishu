二b、底盘补救（第 0 节 · 20 分钟）

卡点话术 / 处置
ima 登录 / 下载失败换手机热点绕开现场网络；仍不行先用 ima 网页版建库，客户端回家再装。不让他原地反复重试。
公众号注册审核中"审核走流程不挡今天的事——我们用预览 / 草稿箱验收双出口，不承诺当天群发。"
AppSecret / IP 白名单"今天只记录 AppID 和配置入口的位置，不现场配 AppSecret、不动白名单——涉及账号安全与审核风险，回去照文档自己配。"
新老分流新学员跟第 0 节清单做；老学员做进阶「回灌」：首页文案存进库 + 公众号发一条「我要开个网站」，不空等。

巡场优先级：未上线 > 底盘未补齐 > 产线未跑通。组长五职责：登记 · 计时 · 带圈 · 收反馈 · 30 天督导。

双出口演示脚本（3 分钟）：① ima 库里选 2 份素材 → ② workbuddy 生成初稿（口播"人工把关"）→ ③ 出口 A：网站预览刷新出新内容 → ④ 出口 B：同一篇进公众号草稿箱，两张截图并排亮出 → 收口："素材只写一次，处处都在。"

三、三种现场事故的处置话术

① GitHub / 网络挂了："切云跑通——放录好的建站流程，对着任务卡标步骤，回去按卡复现。"（交付物改课后 48h 截图）

② 注册卡住（没验证邮箱/用户名被占）："两人一组共用一台，一人操作一人记录；今晚搞定注册，明天按任务卡 15 分钟复现，截图发群算完成。"

③ 大面积没上线：第 3 节直接从"互评走查"转"清单走查"，明确宣布新验收标准——不能让学员带着"我没做完"的挫败离开。

四、控场红线

每节硬卡时间，宁可少讲一个锚点，不可拖延动手时间。
A1 必须给显像提问，冷场时讲师先自曝一个"自己网站走过弯路"的案例（30 秒）做示范。
A2 必须落到"谁 + 何时 + 做什么 + 到什么程度"，缺一项就请学员补。
不承诺"马上有人看/带来客户"——口径："先让名字上线，阵地靠 30 天更新长出来"；12 人坐 3–4 组，助教配比 ≥1:6。
chai.aibay.asia 就是活教材——随时切来讲"同样的结构"，但别贬低学员的"丑站"。
