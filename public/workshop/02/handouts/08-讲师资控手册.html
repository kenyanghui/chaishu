三、三种现场事故的处置话术

① GitHub / 网络挂了："我们切云跑通——我放刚才录好的完整建站流程，大家对着任务卡标出每一步，回去按卡复现。"（交付物改课后 48h 截图）

② 学员 GitHub 注册卡住（没验证邮箱/用户名被占）："两人一组共用一台能跑的，一人操作一人记录；卡住的今晚搞定注册，明天按任务卡 15 分钟自己复现，截图发群算完成。"

③ 大面积没上线：第 3 节直接从"互评走查"转"清单走查"，明确宣布新验收标准——不能让学员带着"我没做完"的挫败离开。

四、控场红线

每节硬卡时间，宁可少讲一个锚点，不可拖延动手时间。
A1 必须给显像提问，冷场时讲师先自曝一个"自己网站走过弯路"的案例（30 秒）做示范。
A2 必须落到"谁 + 何时 + 做什么 + 到什么程度"，缺一项就请学员补。
不承诺"网站马上有人看/带来客户"——口径统一为"先让名字上线，阵地靠 30 天更新长出来"；10 人坐 2–3 组，助教配比不低于 1:5。
本站 chai.aibay.asia 就是活教材——随时切给它讲"同样的结构"，但别贬低学员的"丑站"。
