## 📋 Skill 简介

### 它是什么

**AI 拆书工坊**是一个完整的拆书自动化管线：

```
输入：一本致用类书籍
  ├─ 第1步 女娲蒸馏 → 作者思想知识图谱
  ├─ 第2步 仓颉拆书 → 教练 SKILL.md（核心产出）
  ├─ 第3步 高清大图 → HTML 信息图
  ├─ 第4步 网站构建 → React 展示页面
  └─ 第5步 达尔文进化 → 持续优化迭代
输出：一套可用的教练技能体系 + 展示网站
```

### 为什么做这件事

太多人读书"读完就忘"，因为没有**产出机制**。拆书帮的 RIA 拆书法给了方法，但缺一条流水线——让拆书的产出自动变成可搜索、可分享、可复用的技能资产。

我是拆书帮三级拆书家，手头有 69 本书的拆页，但它们躺在笔记本里。我给这些经验造了一条 AI 流水线。

### 适合谁

| 人群 | 价值点 |
|------|--------|
| **拆书家** | 拆过的书不再"吃灰"，自动变成在线技能库 |
| **知识工作者** | 把读过的书转化为可调用的方法论 |
| **终身学习者** | 建立个人知识体系，持续进化 |

## 🔨 创作过程（核心）

### 缘起

2026 年，我通过拆书帮拆书家认证。按理说这是终点，但我过去参与拆书积累了不少东西，手头有69本书的拆页、数百张 RIA 便签，沉默在笔记本里。**它们应该发挥更大的价值**。

### 架构演进

最初的想法很简单：把 RIA 便签整理成 Markdown 文件。但很快发现不够——光有文件别人怎么找到？怎么筛选？

```
Markdown 文件
  → SKILL.md（可执行的教练框架）
    → HTML 信息图（知识视觉化）
      → React 网站（在线搜索 + 筛选）
        → 达尔文进化（持续优化技能质量）
```

### 五步管线详解

#### 📦 数据层：hotBooks.js（原料仓库）

所有拆书数据统一管理。69 本书、156 场拆书活动，每场包含完整的 RIA 拆页：

```javascript
const hotBooks = [
  {
    title: '高效能人士的七个习惯',
    author: '史蒂芬·柯维',
    category: '管理领导',
    sessions: [{
      title: '移情聆听',
      rias: [{
        r: '柯维提出：移情聆听五个阶段...',
        i: '移情聆听不是被动地听...',
        a: '下次冲突时先复述对方观点...',
        level: 'TF1-1',
      }]
    }]
  }
]
```

#### ⚙️ 管线层：pipeline-cangjie.js（核心引擎）

这是整个系统的核心，`scripts/pipeline-cangjie.js`。它做的事情：

```
hotBooks.js → 逐本逐场解析
  ↓
提取 RIA 结构（支持 20+ 种格式变体）
  ↓
智能识别 What → Why → How → Where 框架
  ↓
自动检测 TF 等级（TF1-1 ~ TF3-3）
  ↓
生成 SKILL.md（frontmatter + 方法论 + 教练流程 + 出处）
  ↓
同步更新 skills.js（网站数据源）
  ↓
✅ 147 个 SKILL.md 自动生成
```

**技术亮点**：正则引擎覆盖所有 RIA 格式变体；从全文自动提取编号步骤；自动归类到对应 TF 学习等级。

#### 🖼 信息图层：pipeline-hd-image.js

把每个 SKILL.md 转化为可视化 HTML 信息图：

- 自包含 HTML，打开即用，无外部依赖
- 暗色主题，适配网站风格
- 按 TF 等级配色：TF1=靛蓝 / TF2=青色 / TF3=琥珀
- 响应式设计，手机/平板/桌面均可阅读

**产出**：144 张信息图，每个技能一张。

#### 🌐 展示层：React SPA

技术栈：**React + Vite + Tailwind CSS + Framer Motion**

```
6 个主要路由，7 大分类，50+ 组件，暗色主题，SPA 架构
```

| 页面 | 路由 | 功能亮点 |
|------|------|----------|
| 🏠 首页 | `/` | 数据总览 + 学习入口 + 成长之路导航 |
| 🔥 热门拆书 | `/hot` | 21 本书按分类展示，点击查看拆页 |
| 🛠 技能工坊 | `/skills` | **搜索框实时过滤 + TF 等级筛选 + 计数** |
| 🧭 学习路径 | `/learning-path` | TF1→TF2→TF3→S级 四级递进 |
| 🖼 高清大图 | `/hd-gallery` | 7 大分类 + AI 封面图 |
| 🔗 技能融合 | `/skill-fusion` | 8 个思想体系跨书组合 |

#### 🧬 第5步：达尔文进化 — 永不停止的优化

技能不是一次性的。达尔文管线持续给每个 SKILL.md 评分，然后基于评分自动优化——就像生物进化一样，不进则退。

## 📖 使用步骤

### 方式一：直接用这个 Skill

在 Trae SOLO 中加载本 Skill 后，直接说：

> "我想拆《刻意练习》，作者安德斯·艾利克森"

AI 会自动执行：**作者蒸馏 → 技能提取 → 推荐学习路径**

### 方式二：搭建自己的拆书网站

```bash
# 1. 克隆项目
git clone https://github.com/kenyanghui/chaishu.git my-chaishu
cd my-chaishu

# 2. 安装依赖
npm install

# 3. 替换数据
# 编辑 src/data/hotBooks.js，放入你的拆书拆页

# 4. 运行管线（一键生成）
node scripts/pipeline-cangjie.js    # 拆页 → SKILL.md
node scripts/update-skills.js       # 更新网站数据
node scripts/pipeline-hd-image.js   # 生成信息图

# 5. 本地预览
npm run dev

# 6. 构建 + 部署
npm run build
git push （GitHub Actions 自动部署到 Pages）
```

### 方式三：在线体验

不需要安装，直接访问：https://kenyanghui.github.io/chaishu/

## 💭 总结与思考

### 最自豪的

1. **端到端完整性**：从一本书到 147 个可用教练技能，再到完整展示网站，所有环节自动衔接
2. **搜索体验**：147 个技能 0.1 秒出结果，按 TF 等级一键筛选——不仅是"展示"，更是真正可用的工具
3. **知识视觉化**：144 张信息图 + 7 张 AI 封面图
4. **数据驱动**：69 本书、156 场拆书、147 个技能——每个数字背后都是真实的拆书实践，不是空泛概念

### 遇到的挑战

| 挑战 | 解决方案 |
|------|----------|
| RIA 格式不统一（20+ 种变体） | 正则引擎统一解析 |
| 自动分类到 TF 等级 | 等级检测算法自动归类 |
| 信息图文字量大 | 放弃 AI 生图方案，改用 HTML 管线 |
| 搜索性能 | `useMemo` 缓存 + 前端过滤 |

### 后续规划

- [ ] **ljg-card 管线**：自动生成 Anki 间隔复习卡片
- [ ] **AI 自动拆书**：用户只提供书名，AI 自动搜索拆页并运行管线
- [ ] **社区共建**：支持多人协作拆书
- [ ] **扩展到 200+ 本书**

### 一点感悟

> **AI 不是替代人拆书，而是让拆书的产出能规模化、系统化、可视化。**

拆书帮的 RIA 拆书法是经过 10 年验证的方法论。AI 的价值不是创造新方法，而是让这个方法的产出能被更多人看见、使用和持续优化。

如果你也用 RIA 拆书法读书，试试这个技能——把你手头正在读的那本书跑一遍管线，看看 AI 拆出来的技能和你手动拆的有什么不同。
